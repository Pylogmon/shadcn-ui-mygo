# Select composition

Run `go run ./examples/select-composition`. `-dark`, `-open` and `-snapshot /path/select.png` also work. The three operation areas cover the fixed 15 collection recipes and seven standalone examples through a shared workbench, independent manual slots, and dialog/system-menu examples. `source-coverage.json` records original blob/hash/definition lines and exact interactive verification names; it is a derived mapping.

The workbench changes basic/groups/100-item/multiple/rich-plan/disabled-item data, all six sides, alignment mode, size, icons, inline Field layout, disabled/invalid state and menu color. Its submission button reads the same caller-owned selection state. The manual collection deliberately supplies no Root Options; its Item/Group/Label slots register native options and final accessibility positions in the same build.

`SelectRoot` owns no visual wrapper. Its mount releases Local state when removed. `SelectState` contains values and open only; native runtime state keeps value/geometry/Handle snapshots, and the build supplies current callbacks. Every public slot rejects an expired scope. Use `List` inside `Content`, then `Group`/`Item`; `Label` belongs inside `Group`. `Content` deliberately does not silently recreate those slots. `SelectWith` and the original `Select`/new `MultiSelect` share this core; original `NativeSelect` remains an OS single-selection menu adapter.

`SelectRootProps.UnselectedValue` explicitly maps a selectable empty/placeholder item to no value. Without it, an empty string is a valid identity. Keep application objects outside the widget and use stable string identities plus `ValueContent`/`ItemContent` for the fixed rich Plan recipe. Application-controlled form submission may call `Scope.FormValues` during the current build or read `SelectState`; this does not create a browser form/validation/autofill engine.

Default Content aligns selected text over the actual value and uses native bounded scrolling with row reveal and hover arrows. This profile has no content animation, matching the fixed wrapper. `AlignItemWithTrigger: &falseValue` enables ordinary side/align/offset placement, logical RTL and the shared fixed 100ms Base/Vega retained inert motion. Translucent menu profiles inherit the committed genuine scene backdrop and no-animation policy. Independent-window desktop adapters retain their own API; the new compound slots are current-window native controls.

Native input, focus, scrolling and pixels are exercised by Go tests. Real screen readers, operating-system IME candidate windows and Cocoa cancellation, Windows/Linux runtime and multi-display acceptance remain platform validation. No generic unused Base configuration universe is presented as implemented.

## Gallery source compositions

The Gallery Forms & controls page adds **Select configuration** with all seven
docs examples and fifteen Create sections, as22 independent configurations.
The fixed revision is `8ab27715521cbd4f87ae6886cd989cbb678f6de7`.
[`source-map.json`](source-map.json) records all nine original files with byte
lengths, SHA-256, Git blobs, pinned raw URLs and per-configuration mapping.
The existing standalone workbench and its `source-coverage.json` remain usable.

Docs preserve the192-DIP Fruits example, the320-DIP Align Item switch with
Banana/true defaults, Fruits/Vegetables groups, all27 timezones in five groups,
disabled and invalid fields, and verbatim Arabic/Hebrew/English groups with the
128-DIP trigger. Create preserves Basic, all six independent112-DIP sides,
two sizes of Chart Type icon content, groups,100 original Item0..99 values,
seven-fruit multiple selection and its count renderer, both sizes, three rich
subscription Plans with Starter as default, adjacent Submit buttons, disabled
Grapes in the item-aligned collection, Field/description, both invalid layouts,
inline real input/filter/native sort menu, disabled root and the original Dialog.
Configuration, language and each source instance retain separate drafts.

Source listboxes use the complete current-window public `control.SelectRoot`
slots, including item-aligned opening and multiple selection. Only the Gallery
configuration/language selectors follow the global Flyout/Native setting. The
current `desktop.Select` facade is a single-string independent Menu adapter;
it does not expose rich multiple/item-aligned Select slots. Those source
behaviors are retained in the current-window component instead of silently
replacing them with a smaller desktop menu. This Gallery stage does not claim
an independent rich Select Flyout or an operating-system multi-select menu.
The source Inline `NativeSelect` is always the real OS single-selection route.
The separate Native Select collection is not counted among these22 recipes.

Explicit source widths are retained. Unspecified CSS natural widths use a
384-DIP native card cap; sides/inline use the available width up to560DIPs.
On very narrow inline layouts, an accessible horizontal viewport retains both
fixed140-DIP selectors and at least32DIPs of real editable input. Popup bounds,
scrolling and item alignment use the existing native Select runtime and actual
window size. Source nullable rendered items map through a private stable
identity to `SelectSelection{Valid:false}`; groups/timezones that do not render
that placeholder do not gain a synthetic selectable row. Plan objects use name
identities and their full original descriptions, with exact rich item/value
content. Source icon placeholders use existing on-demand Material SVGs.

The source timezone flow exposed an item-aligned runtime defect: edge fitting
was applied before an offset calculated from the raw anchor, moving long
panels above the window; native End reveal also ignored overlaid arrow gutters.
The SDK now compensates from the fitted attachment origin, bounds expansion
inside the window and reveals keyboard-active rows outside arrow gutters.
The actual last-row pointer click and Home/End/focus return are checked in the
existing long-list flow. User wheel scrolling remains free after the one-shot
reveal; no artificial maximum height is added to hide the defect.

Submit buttons capture local values and increment a local action count; the
original examples provide no network/transport handler. No Enter handler is
added. Source drafts and snapshots stay in application memory. Persistent
state contains data and public `SelectState` only, never Context, Element,
SelectScope, FieldScope or frame callbacks. No new font, image or dependency is
introduced.

`TestSelectCompositionsSourceWorkflow` is one public native-input flow through
all recipes, pointer/keyboard selection, real disabled/error state, groups,
100-item and timezone scrolling, rich plans, multiple counts, buttons, inline
editing/native sort, Dialog, Hebrew/narrow layout and hide/style draft retention.
Set `GALLERY_SELECT_COMPOSITION_SNAPSHOT_DIR` to export four representative
software PNGs. Injected configuration-menu windows and these native software
images do not establish real OS tracking/window placement, AT/IME, multi-display,
Windows/Linux runtime or complete font/platform/visual acceptance.
