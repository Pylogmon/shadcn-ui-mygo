# Input source compositions

Gallery's Forms page offers 25 Input configurations: all 15 docs examples and 10 Create sections at shadcn/ui revision `8ab27715521cbd4f87ae6886cd989cbb678f6de7`. The default is the docs' protected API Key editor. The 17 original files, their Git blobs, SHA-256 values and pinned URLs are listed in [`source-map.json`](source-map.json).

Docs cover API Key, Basic, Username Field, Field Group, Disabled, Invalid, Picture File, Inline Search, Grid, Required, Beta Badge, Input Group, Button Group, Contact Form and RTL. Create separately preserves Basic Email, Invalid, With Label, With Description, Disabled, Input Types, With Select, With Button, With Native Select and Contact Form. Their placeholders, descriptions, wrappers and required/default differences are not collapsed into a single approximation. Each configuration has independent drafts. Arabic, Hebrew and English API Key translations match the original strings.

Editors are real native MyGo controls. Password uses the protected native editor; Search retains native search semantics. Number uses the typed `NumberInput` with controlled empty presence, so its original `123` placeholder is visible before a number exists. Date and Time use the real native localized date picker and time segments. File invokes the public asynchronous native file picker and displays actual selected names; the optional value-only picker service is only for a clearly injected test backend. No text editor pretends to be a file/date/time control.

Date/Time cannot express HTML's empty/unset value through the current public SDK: this native example starts Date at the local day and Time at midnight. These are explicit remaining source-empty-state differences. Native date popup placement and time formatting follow the platform. Email, telephone and URL use native text editors with the source labels/placeholders, without browser keyboard-purpose/autofill or automatic live constraint bubbles.

The two contact forms and Field Group perform local application actions. Docs Contact Form requires its Name; Create Contact Form does not. An empty optional email is valid, and nonempty ASCII email shape follows the [WHATWG email definition](https://html.spec.whatwg.org/multipage/input.html#email-state-(type=email)); submission trims surrounding ASCII whitespace. No browser IDNA conversion, live input sanitization, validation bubble, server request or email delivery is claimed. Submit captures a local value snapshot; Reset restores the Field Group's empty values; Cancel records a local intent. Source descriptions about API-key encryption and email privacy remain sample copy. Values and snapshots stay in application memory; no encrypted storage, upload backend or security service is implemented.

Input Group prefix/icons and the joined Button Group retain a real editable target and label association. Button Group keeps its source's ordinary text editor; only source inputs explicitly declared as search use native search semantics. Search buttons capture local snapshots; Enter has no added submission handler. Currency uses a 128-DIP trigger with a styled Flyout or system menu according to Gallery's menu setting. The source explicitly named Native Select country-code menu always uses the OS route. Narrow grid/form fields shrink without replacing their editors; the source two-column layouts are retained. Icon content uses on-demand Material Symbols SVG equivalents; no font, image asset or runtime network loader is added.

`TestInputCompositionsSourceWorkflow` is one public-input flow through real protected/text editing, independent configurations, disabled/invalid state, local required/email validation/reset, current form selects, joined and addon focus, typed number/date/time, an explicitly injected asynchronous file picker, narrow grid, Hebrew, hide/return and a styled configuration selector. Optional software PNGs use `GALLERY_INPUT_COMPOSITION_SNAPSHOT_DIR`. These images and the injected popup/file services do not establish real OS picker/window behavior, IME, assistive technology, multi-display or full platform/visual acceptance.

Only strings, numbers, times, path lists, local form snapshots, stable public handles and the optional value-only picker service persist in the application model. The parent Window is passed into each current build. No Context, Element, FieldScope or frame callback is held by the model.
